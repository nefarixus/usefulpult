# Домашний пульт

Уютный тёмный компактный виджет-дашборд: сверху панель иконок для
переключения между разделами (время, погода, курс валют, дела, случайные
слова), внизу — сам активный раздел. Next.js (App Router) + TypeScript +
Tailwind CSS + lucide-react, без сервера и без БД — всё либо публичные
бесплатные API без ключей, либо localStorage в браузере.

## Запуск

Нужен установленный [Node.js](https://nodejs.org) 18+.

```bash
npm install
npm run dev
```

Открой http://localhost:3000

## Сборка для продакшена

```bash
npm run build
npm start
```

## Из чего сделано

- **Next.js 14 / React 18 / TypeScript** — фреймворк и типизация
- **Tailwind CSS** — стили, все цвета и шрифты вынесены в `tailwind.config.ts`
- **lucide-react** — иконки (погода, дела, курсы и т.д.)
- **Open-Meteo** (`api.open-meteo.com`) — погода, ключ не нужен
- **Frankfurter** (`api.frankfurter.dev/v1`) — курсы валют (ECB), ключ не нужен
- Геолокация браузера для погоды, с фоллбэком на координаты по умолчанию

## Что можно быстро поменять

- **Город по умолчанию для погоды** — `FALLBACK_COORDS` в
  `components/WeatherWidget.tsx`
- **Валюты в конвертере** — массив `TARGETS` в `components/CurrencyWidget.tsx`
- **Цитаты дня** — массив `QUOTES` в `lib/quotes.ts`
- **Слова для генератора** — массив `AESTHETIC_WORDS` в `lib/words.ts`
- **Пункты чек-листа по умолчанию** — `DEFAULT_ITEMS` в
  `components/GameChecklist.tsx` (дальше пользователь сам добавляет/удаляет
  через интерфейс, сохраняется в localStorage)
- **Цвета/шрифт** — `tailwind.config.ts` (палитра `home.*`) и шрифт в
  `app/globals.css` (сейчас Nunito)

## Автообновление

Приложение проверяет обновления через `electron-updater` + GitHub Releases
(при старте и раз в 4 часа, плюс вручную через трей → «Проверить
обновления»). Чтобы это заработало, один раз настрой публикацию:

1. Создай (или используй) публичный GitHub-репозиторий для проекта.
2. В `package.json` в секции `build.publish` замени `YOUR_GITHUB_USERNAME`
   на свой логин на GitHub (и `repo`, если репозиторий называется иначе).
3. Подними версию в `package.json` (`"version"`) перед каждым релизом —
   `electron-updater` ориентируется именно на номер версии.
4. Сделай [токен доступа GitHub](https://github.com/settings/tokens) с
   правом `repo`. Скопируй `.env.example` в `.env` и впиши туда токен:
   ```
   GH_TOKEN=твой_токен
   ```
   Файл `.env` уже в `.gitignore` — он не попадёт в репозиторий. Дальше
   просто:
   ```
   npm run electron:publish
   ```
   Токен подтянется из `.env` автоматически (через `dotenv-cli`), не
   нужно каждый раз прописывать переменную окружения вручную. Эта команда
   соберёт приложение и сама зальёт установщик + файл `latest.yml` в
   GitHub Releases. Дальше все, у кого уже стоит приложение, получат
   новую версию автоматически при следующем запуске — раздавать `.exe`
   вручную больше не нужно, кроме самого первого раза.

## Автообновление и первая установка

Первый `.exe` всё равно нужно дать тестерам вручную (обычным способом —
через мессенджер, диск и т.д.). После первой установки все следующие
версии будут приходить сами через GitHub Releases.

Тот же дашборд, но как отдельное приложение: без рамки, лежит на рабочем
столе под иконками (как в Rainmeter), управляется через иконку в трее.

### Запуск в режиме разработки

```bash
npm install
npm run electron:dev
```

Поднимет Next.js dev-сервер и откроет Electron-окно поверх него.

### Сборка установщика (.exe)

```bash
npm run electron:build
```

Соберёт статическую версию сайта и упакует её в `dist-electron/` —
получится обычный `.exe`-инсталлятор (NSIS) и портативная версия.

### Как устроено окно

- Без рамки, без иконки в панели задач — только иконка в трее
- Обычное плавающее окно поверх рабочего стола (не встроено под иконки).
  Перетаскивается с любой точки фона, где нет кнопок/полей ввода —
  вручную через IPC (`electron/preload.js` + `components/DragHandle.tsx`),
  без нативного OS-drag
- Через иконку в трее: показать/скрыть окно (пункт меню сам показывает
  актуальное состояние — «Показать» или «Скрыть»), выйти

### Про "приклеивание" к рабочему столу

В коде (`electron/main.js`, функция `embedIntoDesktop`) остался трюк,
которым пользуется Rainmeter — реparenting окна в системный `WorkerW`,
чтобы оно лежало под иконками рабочего стола. Он **выключен по
умолчанию** (`pinnedToDesktop = false`): на практике выяснилось, что
такое встраивание может ломать точность попадания кликов по кнопкам —
рендер идёт нормально, а вот куда реально прилетает клик мыши, начинает
не совпадать с тем, что видно на экране (это отдельная, недокументированная
часть Windows, и трюк с `SetParent` официально решает только отрисовку,
не ввод).

Если всё же хочется попробовать — поменяй `pinnedToDesktop` на `true` в
начале `electron/main.js` и пересобери. Если кнопки перестанут отвечать —
верни обратно на `false`.
